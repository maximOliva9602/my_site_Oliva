# Студія масажу Oliva — сайт

Темний luxury-лендінг для масажної студії **Oliva** (Київ, Солом'янський район,
вул. Борщагівська 145). Чистий HTML/CSS/JS, який роздається через невеликий
Node/Express-сервер — щоб згодом без переробок додати живий онлайн-чат і
деплоїти на **Railway**.

## Запуск локально

**Варіант 1 — просто відкрити файл.** Відкрийте `public/index.html` у браузері.
Працює без сервера (чат у режимі «месенджери»).

**Варіант 2 — через сервер (як на Railway):**
```bash
npm install
npm start
# http://localhost:3000
```

## Деплой на Railway

1. Залийте проєкт у GitHub-репозиторій.
2. Railway → **New Project → Deploy from GitHub repo** → оберіть репозиторій.
3. Railway сам визначить Node, виконає `npm install` і `npm start`.
4. **Variables** → задайте `ADMIN_PASSWORD` (пароль менеджера для входу на `/admin`).
   `NODE_ENV=production` Railway виставляє сам (потрібно для secure-cookie).
5. Прив'яжіть домен у Settings → Domains.

## Онлайн-чат та адмін-панель

Живий чат працює без сторонніх сервісів (Socket.IO):

- **Клієнт** пише у віджеті прямо на сайті (нічого не встановлює).
- **Менеджер** заходить на **`/admin`**, вводить `ADMIN_PASSWORD`, бачить список діалогів
  і відповідає в реальному часі. Сторінка адаптивна — зручно відповідати з телефона.
- Кілька клієнтів — кожен окремим діалогом у списку (не плутаються).
- Якщо сервер недоступний (напр. відкрито `index.html` як файл) — віджет показує
  запасні кнопки месенджерів.

> ⚠️ Історія діалогів зберігається **в памʼяті** і скидається при перезапуску/редеплої.
> Це свідоме рішення замовника (чат). **CRM — навпаки, зберігається у SQLite** (див. нижче).

## CRM: онлайн-запис, кабінети, нагадування

Власна CRM поверх того ж сервера. Дані — у **SQLite** (`better-sqlite3`) одним файлом
на Railway Volume. Жодних підписок: розсилка через **TurboSMS** (оплата за повідомлення).

**Сторінки:**
- **`/booking`** — публічний онлайн-запис для клієнта: послуга → майстер (або «будь-який»)
  → дата → **тільки вільні віконця** → ім'я+телефон → підтвердження. Усі кнопки
  «Записатися» на сайті ведуть сюди.
- **`/cabinet`** — кабінет CRM (рольовий):
  - **Власник** (вхід лише паролем `ADMIN_PASSWORD`): записи на будь-яку дату й по майстрах,
    ручне створення/перенесення/скасування, **клієнти** (історія, візити, коментар),
    **послуги** (тривалість+ціна), **майстри** (профіль, послуги, **графік+перерви**,
    **вихідні**), **доступи** майстрів, **журнал сповіщень** зі статусами.
  - **Майстер** (вхід логін+пароль зі вкладки «Доступи»): лише свій графік, свої записи
    (підтвердити/завершити/скасувати/перенести) і своїх клієнтів.

**Логіка вільних віконець** (`crm/slots.js`): враховує графік майстра по днях тижня,
перерви, вихідні (`time-off`), наявні записи й **тривалість послуги** (послуга не пропонується,
якщо не вписується у зміну чи перетинає перерву/інший запис). Минулі дати/години приховані.
Подвійний запис на один час неможливий (перевірка в транзакції → `409`).

**Нагадування** (`crm/scheduler.js`, без зовнішнього cron): після запису клієнту йде
**підтвердження**; за **24 год** — нагадування; опційно ще за `REMINDER2_HOURS` годин.
Канал — Viber з фолбеком на SMS (TurboSMS). Статус кожного повідомлення (відправлено/
доставлено/не доставлено) пишеться у БД; фінальний статус приходить **вебхуком**
`POST /api/webhooks/turbosms` або опитуванням.

**Драйвер розсилки** перемикається через `NOTIFY_DRIVER`:
- `console` — лог у консоль (локальна розробка, дефолт);
- `telegram` — шле у студійний Telegram-чат (тимчасово, поки нема TurboSMS);
- `turbosms` — бойовий Viber→SMS (коли замовник дасть токен і зареєструє відправника).

### Env для CRM (повний перелік — у `.env.example`)
| Змінна | Призначення |
|--------|-------------|
| `ADMIN_PASSWORD` | пароль власника для `/admin` і `/cabinet` |
| `DB_FILE` | **абсолютний** шлях до SQLite на Volume, напр. `/app/data/oliva.db` |
| `TZ` | `Europe/Kyiv` (важливо для слотів і нагадувань) |
| `NOTIFY_DRIVER` | `console` \| `telegram` \| `turbosms` |
| `STUDIO_ADDRESS` | адреса в тексті нагадувань |
| `REMINDER2_HOURS` | друге нагадування за N годин (0 = вимкнено) |
| `LEAD_MIN` | запас від «зараз» для слотів на сьогодні (хв) |
| `TURBOSMS_TOKEN` / `TURBOSMS_SENDER` / `TURBOSMS_VIBER_SENDER` | дані TurboSMS |
| `TURBOSMS_WEBHOOK_SECRET` | секрет для вебхука статусів |

### Деплой CRM на Railway
1. **Підключити Volume** і змонтувати, напр. на `/app/data` (там і блог `posts.json`, і `oliva.db`).
2. У **Variables** задати `DB_FILE=/app/data/oliva.db`, `TZ=Europe/Kyiv`, `ADMIN_PASSWORD`,
   `NOTIFY_DRIVER` (спершу `console` або `telegram`).
3. `better-sqlite3` — нативний модуль; Node закріплено у `engines` (`22.x`) та `.nvmrc`.
4. Після старту: зайти у `/cabinet` власником → додати майстрів, послуги, графіки → перевірити `/booking`.
5. Коли буде акаунт TurboSMS — задати `TURBOSMS_*`, `NOTIFY_DRIVER=turbosms`, прописати URL вебхука
   `https://<домен>/api/webhooks/turbosms?secret=<TURBOSMS_WEBHOOK_SECRET>` у кабінеті TurboSMS.

## 📋 Потрібно від замовника (заміна плейсхолдерів)

Шукайте у коді позначки `REPLACE_ME` та атрибути `data-replace="..."`.

| Що | Де замінити | Примітка |
|----|-------------|----------|
| **Фото галереї** | `public/index.html` → секція `#gallery` (`src` зображень) | реальні фото з Instagram @oliva_massage_studio |
| **Фото майстрів** | секція `#team` (зараз ініціали-плейсхолдери) | + підтвердити імена/ролі майстрів |
| **Hero-відео** | `assets/video/hero.mp4` + розкоментувати `<video>` у `#hero` | ≤8–10 МБ, 1080p, без звуку (muted) |
| **Відео/фото фітобочки** | `assets/video/phyto.mp4` або `img` у `#phyto` | аналогічно |
| **YouTube** | `data-replace="youtube"` (топ-бар, контакти) | вставити реальний URL каналу |
| **Telegram** | `data-replace="telegram"` (топ-бар, чат, контакти) | username/посилання бота/каналу |
| **Threads** | `data-replace="threads"` (топ-бар) | реальний URL |
| **Facebook** | `data-replace="facebook"` (топ-бар) | реальний URL сторінки |
| **Ціни/послуги** | секція `#services` + `assets/js/i18n.js` | звірити з актуальним прайсом |

> Логотип уже встановлено: `public/assets/img/logo.png`. Замінюється тим самим іменем файлу.

## Hero-відео: чи витримає сайт?
Так. Широкоформатне відео працює без проблем, якщо це **стиснений `.mp4` (H.264)
до ~8–10 МБ, 1080p, без звуку**, з `muted autoplay loop playsinline` і фото-постером
на час завантаження. Великі (50+ МБ) файли сповільнять перше відкриття — у такому
разі краще завантажити на YouTube/Vimeo та вбудувати. Розмітка під обидва варіанти
вже підготовлена в `#hero` (і в `#phyto`).
